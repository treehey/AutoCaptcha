# OCR 改进计划

目标：把统一身份认证增强验证码的识别稳定性提升到可持续迭代的状态。v5.0.0 在发布候选冻结后的全新验证集达到 `146/150`（约 `97.3%`），热态 CNN 通常约 `30-45ms`；后续重点转为防回归、样式漂移检测和模型可重复训练。

## 1. 样本与标注

- 每轮采集 30-100 张真实验证码样本。
- 样本、联系表和 `answers.csv` 全部放在 `data/captcha-samples/` 并提交 Git；仅忽略会话产生的 `cookies.txt` 和 `login.html`。
- 禁止清理、移动或通过 junction/worktree 操作样本目录；发布打包只允许读取明确白名单中的运行文件。
- 每轮生成 `contact-sheet.png` 和 `answers.csv`。
- 用户按编号给出答案，例如：

```text
01: 8qWd
02: c3R9
03: hewX
```

## 2. 基准测试

- 建立一键 OCR 回归脚本，读取样本与答案。
- 输出单轮准确率、平均耗时、P50/P95 耗时。
- 输出错误明细：图片编号、正确值、识别值、候选列表、耗时。
- 按实际验证码规则评分：字母大小写不敏感，数字与字母仍严格区分。
- 保留混淆矩阵，重点追踪 `j/p/i`、`5/S`、`B/D`、`U/t`、`Q/O/0` 等高频混淆。

当前基准结果：

- v5.0.0 使用 `round-024` 至 `round-029` 共 180 张训练和开发，按轮 OOF 选择模型种子与训练轮数。
- `round-030` 至 `round-033` 共 120 张未参与训练的独立留出集：插件真实流程 `118/120`，约 `98.3%`；平均约 `0.06s/张`。
- `round-034` 至 `round-038` 共 150 张在发布候选冻结后新采集，只评测一次且未参与任何调参：`146/150`，约 `97.3%`；平均约 `0.055s/张`。
- 两批未训练样本合计 `264/270`，约 `97.8%`；15 轮完整回归为 `444/450`，约 `98.7%`。
- 同一独立留出集下 v4.2.0 默认流程为 `87/120`，约 `72.5%`；v5.0.0 净增 `31` 张。
- `round-024` 至 `round-033` 完整回归为 `298/300`，约 `99.3%`。该数字包含训练轮，只用于防回归，不能替代独立留出指标。
- 按独立留出集估算，平均约 `1.02` 次尝试可识别成功，2 次内成功概率约 `99.97%`。

注意：`round-024` 至 `round-029` 已用于 v5.0.0 训练；`round-030` 至 `round-038` 均已用于本版本验证。任何继续根据这些错误进行的调整，都必须重新采集全新 holdout 才能宣称泛化提升。早期 `round-010` 至 `round-023` 的回归报告和模型衍生特征仍可用于历史对比，但源图片因工具误操作已无法恢复，不得计入当前可重跑基准。

当前反过拟合准则：

- 不再新增针对单个样本或固定字符对的窄规则。
- 优先采用可跨样本解释的整码候选聚类、大小写不敏感投票、去线候选旁证和 fallback 触发规则。
- 接受优化前，至少同时跑开发回归集和 holdout；若只提升旧轮、压低 holdout，则视为过拟合。

字符集观察：

- `round-001` 至 `round-011` 的 330 个标注、1320 个字符中，按大小写不敏感统计，`0`、`1`、`o/O`、`z/Z` 从未出现。
- 大小写敏感统计中，`l` 和 `I` 也未出现，但 `L` 与 `i` 出现过；直接排除 `l/I` 没有提升准确率，且会让个别样本变成空结果。
- 当前采用保守 OCR 白名单：排除 `0/1/o/O/z/Z`，保留 `l/I` 作为 Tesseract 的形状中间态。
- 白名单 A/B：全量字符集、激进白名单、保守白名单在 `round-010` 至 `round-011` 上均为 `41/60`；保守白名单能减少不可能字符输出，但样本级准确率瓶颈仍在干扰线、切分和高频形状混淆。

## 3. 速度优化

- CNN 模型与权重使用浏览器缓存，热态直接识别通常约 `30-45ms`。
- 仅当首位 `c/e` 需要保护、字符置信度低于开发集阈值或 CNN 异常时启动 Tesseract。
- 保持旧 OCR worker 延迟初始化，避免绝大多数 CNN 快路径承担 WASM 初始化成本。
- 后续可评估 Float16/Int8 权重量化，但必须逐张验证与 Float32 输出一致或不降低新 holdout。

## 4. 准确率优化

- 原始彩色字符槽 CNN：直接学习主体粗笔画、颜色和跨槽细干扰线，不再依赖先删除干扰线。
- 固定四槽带重叠裁剪：保留字符边缘，避免动态连通域被干扰线拖偏。
- Tesseract 兜底：只在 CNN 保护条件、极低置信或加载异常时运行多变体 OCR。
- 对每轮错误样本先归因，再抽象为跨样本规则；禁止直接追加只服务单张图的修正。

实验结论：

- `scripts/run-segmentation-experiment.mjs` 验证了“动态切 4 段 + Tesseract 单字符 `psm 10`”方向，`round-012` 首轮仅 `8/30`。切框大体可用，但单字符 Tesseract 对当前字体和噪声不稳定，不能直接替代整行 OCR。
- `scripts/run-template-experiment.mjs` 验证了本地模板分类器。模板单独做整码识别仍偏低，但字符级准确率在 leave-one-round-out 中常见 `80%+`。
- PSM 7 与 PSM 13 的候选存在互补，但开发集门控在最终集只净增 1 张，不值得增加第二套完整 OCR 的时间成本。
- 模板候选 beam 在开发集最高 `134/180`，最终集最高 `89/120`，无法解决正确字符未进入 OCR 候选的问题，因此不再作为主方向。
- 原始彩色字符槽 CNN 的三个独立随机种子在最终集整码达到 `113-117/120`；按开发 OOF 选择的模型为 `113/120`，结合开发集冻结的 `c/e` 保护与 OCR 回退后达到 `118/120`。
- 后续优化优先增加全新训练轮和新 holdout，或研究模型量化与样式漂移；禁止继续为当前两张错误添加单样本规则。

## 5. 交互优化

- Popup 增加登录助手实时状态：未配置、识别中、已填充、已提交、失败重试。
- 增加选课助手连接检测、最近一轮检测时间、成功课程列表。
- 日志支持清空、复制和状态筛选。
- 减少视觉噪声，统一按钮、状态色和间距。

## 6. 发布质量

- 使用 `scripts/build-package.ps1` 生成干净发布包。
- 发布前检查包内无 `.git`、`dist`、本地样本、临时文件。
- 每次版本更新同步 `manifest.json`、README badge 和 CHANGELOG。
- 发布前运行独立留出集、10 轮完整回归、增强关闭回退测试和发布包解压校验。
