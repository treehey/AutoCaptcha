# 点击式验证码自动识别工作计划

更新日期：2026-07-27

本文是后续实施和发布门槛的当前执行准则；`CLICK_CAPTCHA_ARCHITECTURE_PLAN.md` 继续保留为历史研究与实验记录，其中较早的 `99%` 高置信覆盖率要求不再覆盖本文定义的单次与重试目标。

## 目标

最终交付是一个完全在浏览器本地运行的选课自动登录功能：填写已保存账号密码、识别四个目标字并按正确顺序点击四个候选字、提交登录；遇到三字或低置信验证码时自动刷新，失败时可靠回退或换图重试。

精度目标按优先级定义为：

1. 插件端单张整码准确率至少 `90%`，目标 `95%+`，尽力达到 `99%`。
2. 在能够可靠检测失败并刷新新验证码的前提下，两次尝试的端到端成功率目标 `99%+`。
3. 热态推理 `p95 <= 500 ms`，冷启动 `p95 <= 1500 ms`；新增压缩资源优先控制在 `5 MB` 内，硬上限暂定 `15 MB`。
4. 不依赖云端服务、大模型 API 或远程代码，不新增与功能无关的浏览器权限。

两次尝试的理论成功率为 `1 - (1 - p)^2`：单次 `90%` 时约为 `99%`，单次 `95%` 时约为 `99.75%`。这只在两次验证码近似独立、且页面失败状态能够可靠检测时成立，必须用真实页面验证，不能只凭公式宣称。

## 模块与接口

采用两个深模块，把图像理解与页面操作分开。

### 求解模块

外部接口保持为一个入口：

```ts
solveClickCaptcha(image: ImageData): Promise<
  | { kind: 'solved'; points: Point[]; confidence: number; modelVersion: string; elapsedMs: number }
  | { kind: 'refresh'; reason: 'three-target' | 'unstable-image' }
  | { kind: 'manual'; reason: string; confidence?: number }
>
```

接口不暴露背景减除、分割框、旋转候选、模型张量或排列枚举。实现内部隐藏：

- 画布稳定性与目标数检测；
- 固定背景减除、颜色/轮廓前景提取；
- 四个目标和四个候选的裁剪与归一化；
- 轻量模型和确定性形状分数；
- `4 x 4` 匹配矩阵与 24 个排列选择；
- 置信度校准、模型版本和耗时统计。

离线 Python 参考实现与浏览器 Worker 实现是这个 seam 上的两个 adapter。两者必须对固定夹具输出同一点击顺序，允许的数值误差单独定义。

### 自动点击控制模块

外部接口同样保持小：

```ts
runClickCaptcha(target: HTMLCanvasElement, policy: AutoClickPolicy): Promise<RunResult>
```

实现内部负责等待稳定画布、调用求解模块、三字刷新、坐标映射、按序派发点击、检测页面成功/失败、低置信时最多五次换图重试、人工回退和取消。页面 DOM 是 true external 依赖：正式页面 adapter 读取真实 Canvas 和刷新控件，测试使用内存页面 adapter。

### 未采用的接口形状

- 不把 `preprocess()`、`segment()`、`scorePairs()`、`pickPermutation()` 暴露给 `content-grab.js`；这会形成浅模块并把算法变化扩散到页面脚本。
- 不把识别和 DOM 点击塞进一个不可测试的大函数；图像准确率与页面交互必须能分别验证。
- 不让 Popup 直接控制模型细节；Popup 只保存“是否启用自动点击”和展示状态。

## 技术路线

### 阶段 1：建立不可争议的开发基线

- [ ] 统一一个只读评测命令，输出整码准确率、字符准确率、逐轮结果、三种子均值、延迟和改对/改错列表。
- [ ] 审计当前最终融合中三个种子共同出错的 7 张，以及种子分歧样本；只检查标签、裁剪和算法失败类型，不据此调最终测试。
- [ ] 为固定背景、目标裁剪、候选裁剪和坐标映射建立图片夹具测试。
- [ ] 记录现有形状匹配、DINO、PP-OCR、现有学生四条基线，避免以后重复走失败路线。

完成条件：一条命令可复现所有开发指标，任何模型改动都能看出逐样本收益和回归。

### 阶段 2：把离线教师推向 `95%+`

只增加一个新的互补模态：确定性字形配准。它使用固定背景减除后的轮廓、骨架、距离变换、孔洞/连通分量和有限旋转下的双向 Chamfer 分数，再与冻结 DINO、PP-OCR 分数融合。

- [x] 先实现无训练的轮廓/骨架匹配并按轮交叉验证。
- [x] 分析它是否能修复 DINO + PP-OCR 的共同错误，而不是只提高训练轮次。
- [x] 只在 `001..016` 上选择融合方式和校准参数，至少跑三个固定种子。
- [x] 若形状模态不能带来稳定增益，停止该分支，不继续堆手工规则。

完成条件：开发期分组验证均值目标 `95%+`；最低可接受增益为相对当前教师 `+2` 个百分点，并且最差轮次不下降超过 `2` 个百分点。

### 阶段 3：训练可部署学生

现有从零训练的小 CNN 仅达到 `65%`，不继续微调同一失败配置。优先尝试成熟、浏览器友好的预训练移动骨干，并保持“每个字形编码一次，再计算 16 个轻量匹配分数”。

实验严格按以下顺序，每一步只改变一个主要变量：

1. [x] ImageNet 预训练的 MobileNetV3-Small/EfficientNet-Lite 字形编码器 + 排列损失。
2. 同图困难负样本的监督对比损失，直接强化相似汉字区分。
3. [x] 从最终离线教师蒸馏排列分布，不蒸馏错误的硬 top-1。
4. 使用真实目标字生成候选风格的合成退化：旋转、缩放、剪切、颜色、模糊、笔画缺损、遮挡和真实固定背景。
5. 若模型已达标，再做 INT8/FP16 量化；量化前不牺牲准确率换体积。

完成条件分三级：

- 进入浏览器原型：开发分组验证 `>= 90%`，三种子极差 `<= 3` 个百分点。
- 发布目标：`>= 95%`，热态 Python/ONNX 推理满足延迟预算。
- 冲刺目标：单张 `99%`；若达不到，则依靠可靠换图重试追求端到端 `99%+`。

停止条件：连续三次有原则的实验增益均小于 `0.5` 个百分点，或两个不同移动骨干都低于 `90%`，就停止架构搜索，转向数据与端到端重试质量。

### 阶段 4：模型导出与浏览器一致性

- [x] 导出 ONNX，并验证 PyTorch 与 ONNX 的 600 张夹具点击顺序完全一致。
- [x] 第一版使用本地 ONNX Runtime Web Worker 验证功能和速度，不加载任何远程资源。
- [x] 测量实际新增包体与浏览器热态延迟；浏览器 Canvas 夹具为 `587/600 = 97.83%`、均值 `93.9 ms`、p95 `108.1 ms`。完整结果见 `CLICK_CAPTCHA_RUNTIME_RESULTS.md`。
- [ ] 若运行时包体过大，再把已冻结网络转换到定制二进制并复用/扩展现有本地 CNN 计算器；不在模型尚未达标时提前重写推理引擎。

完成条件：浏览器与离线参考点击顺序 `100%` 一致，热态 `p95 <= 500 ms`，主线程无明显卡顿。

### 阶段 5：插件交互与自动重试

- [x] 在选课面板增加独立的选课系统自动登录开关；默认开启，手动重新识别只标点。
- [x] 状态覆盖等待验证码、识别中、点击中与转人工；标点使用候选字边界框与旁置编号，不遮挡待确认字形。
- [x] 三字验证码直接刷新，不进入模型。
- [x] 置信度低、画布变更、模型异常或采样进行中时不点击。
- [x] 自动点击可在序列中取消；未知尺寸或背景漂移只标点，禁止自动点击；同一失败帧不轮询重试。
- [x] 自动点击开启时，低置信结果最多换图重试 `5` 次；不重复点击同一画布，背景不匹配、模型异常或用户取消时立即转人工。
- [ ] 确认自动点击不影响已有课程监控、自动抢课和手动点击。
- [ ] 保留本地调试日志：模型版本、结果、置信度、耗时、刷新次数；不记录账号密码，不上传图片。

完成条件：离线模拟页面覆盖成功、失败、三字、刷新超时、用户取消和模型异常；已有选课监控回归通过。

### 阶段 6：真实页面与发布验证

- [ ] 先验证页面是否接受扩展派发的坐标事件，是否检查 `event.isTrusted`。
- [ ] 在真实页面先启用“只画预测点、不点击”的影子模式，人工核对至少 30 张。
- [ ] 再进行受控自动点击，验证失败反馈、低置信换图重试和用户取消。
- [ ] 冻结发布候选后采集 `round-021..030`，一次性评测单张准确率与两次流程成功率。
- [ ] 达标后升级大版本（建议 `6.0.0`），更新 README、CHANGELOG、商店说明、权限说明和隐私文档并打包。

发布门槛：

- 插件端全新测试集单张整码准确率至少 `90%`，目标 `95%+`；
- 真实页面两次尝试成功率至少 `99%`，且失败检测无误点击；
- 目标数检测、离线/浏览器一致性、现有登录 OCR 和选课监控回归全部通过；
- 不新增远程代码和数据上传。

## 风险与优先验证顺序

1. **页面可能拒绝合成点击。** 这是最大的非模型风险；浏览器模块完成最小可用事件派发后，应尽早在真实页面验证。如果页面强制 `isTrusted`，普通扩展无法可靠自动点击，项目需改为预测点提示而非承诺全自动。
2. **固定背景或页面布局变化。** 求解模块必须检测尺寸/背景指纹，未知版本直接转人工，不能带着错误坐标点击。
3. **数据同质化。** 当前样本大多来自少量日期和同一环境；新的发布测试必须跨至少两个会话，最好跨日期。
4. **教师上限不足。** 当前教师仅约 `91.7%`；学生不能假定通过蒸馏自然超过教师，必须引入形状配准、预训练移动骨干或更多真实/合成数据。
5. **重试错误相关。** 两次成功率公式依赖新验证码近似独立；真实测试必须报告实际值，不能用理论值替代。

## 下一次对话的自动执行顺序

Codex 在不需要用户输入的情况下依次推进：

1. 建立统一评测与错误审计脚本，确认开发数据和结果可复现。
2. 实现并评测确定性形状配准模态。
3. 选择是否进入三模态教师融合；无增益则立即停止。
4. 训练预训练移动学生，按阶段 3 的顺序做受控实验。
5. 达到 `90%+` 后导出 ONNX，完成离线与浏览器数值一致性。
6. 实现求解模块、Worker、自动点击控制模块和面板状态。
7. 跑全部离线、浏览器夹具和现有插件回归。

每个阶段达到检查点后独立 commit；不 push，除非用户明确要求。实验失败也记录结果，避免下一次重复。
