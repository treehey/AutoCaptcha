# 点击验证码 Round 001 结构分析

分析时间：2026-07-19

## 数据完整性

- 样本数：30
- 每张点击数：4
- 图片尺寸：全部为 `250 x 120`
- 原始导出包：`source-export.json`
- 图片数与元数据样本数一致：30
- 所有点击序列均覆盖四个候选槽位各一次；没有重复点击同一候选或遗漏候选的样本。

Round 001 仅用于开发和可行性验证，不能作为后续泛化准确率结论的测试集。

## 固定布局

| 区域 | 像素范围 | 结论 |
| --- | --- | --- |
| 上方候选区 | `y = 0..99` | 包含四个彩色中文字符与浅蓝干扰背景 |
| 底部指令区 | `y = 100..119` | 黑底白字，所有样本边界一致 |
| 指令前缀 | `x = 45..103` | 固定的“依次点击”文字 |
| 目标字槽位 | `x = 120..133`、`143..156`、`166..179`、`189..202` | 四个待匹配中文字，顺序即点击顺序 |
| 候选槽位 1..4 | `x < 58`、`58..127`、`128..189`、`x >= 190` | 上方四个候选字横向位置稳定且互不重叠 |

候选字符的纵向位置存在变化，因此上方槽位应保留完整 `100px` 高度，不应使用固定纵向裁剪。

## 标注质量

手动点击的横坐标按从左到右排序后，四个候选槽位分别为：

| 候选槽位 | 点击横坐标范围 | 点击纵坐标范围 |
| --- | --- | --- |
| 1 | `12..42` | `17..62` |
| 2 | `73..105` | `16..64` |
| 3 | `138..172` | `25..68` |
| 4 | `202..232` | `43..67` |

30 张样本出现了 19 种不同的点击顺序，说明顺序并非固定，数据能够训练和验证真正的字形匹配，而非位置顺序猜测。

## 工程结论

不需要做通用中文 OCR，也不需要先做不稳定的全图字符检测。首版识别可以固定为：

1. 从底部四个固定槽位读取目标字形。
2. 从上方四个固定槽位读取候选字形。
3. 对每个目标字与四个候选字计算字形相似度。
4. 用一对一全局匹配得到点击顺序。
5. 低置信时只标出建议点击序号，不自动点击。

浅蓝背景会导致简单高饱和连通域切分中文笔画，因此色彩只能作为候选区内的前景增强，不应单独承担字符定位。

## Round 001 基线结果

Round 001 只用于可行性验证，以下结果不能作为发布准确率或泛化结论。

| 方法 | 整张顺序正确 | 单个槽位正确 | 结论 |
| --- | ---: | ---: | --- |
| 色彩前景 + 像素/轮廓字形匹配 | 至多 `3/30` | 至多 `43/120` | 上下字体与变形差异过大，不能作为识别器。 |
| PP-OCRv5 mobile 直接读顶部候选字 | `2/30` | `41/120` | 通用模型无法直接抵抗顶部干扰线和字形扭曲。 |
| PP-OCRv5 mobile 读取底部目标字 | `120/120` 均输出单个 CJK 字 | - | 可作为自动生成训练标签的来源，但仍需按置信度过滤。 |

PP-OCR 顶部直接识别的离线 CPU 用时约为 `110ms/张`（8 个小裁剪）。这不是插件内性能承诺，也不足以弥补目前的准确率缺口。

底部目标字中，`113/120` 的置信度不低于 `0.90`，中位数为 `0.998`。结合人工点击顺序，可以为上方四个候选字自动派生中文标签，而无需逐字人工录入：

```text
底部目标字顺序 + 手动点击槽位顺序 -> 上方候选字标签
```

评测脚本 `scripts/evaluate-click-captcha-ppocr.py` 会把这些结果写入每行的 `derivedCandidateLabels` 字段；低置信目标字应在训练阶段排除或标记为弱标签。

## 修订后的工程路线

首版不能把当前匹配分数用于自动点击。正确的下一步是单独训练“顶部变形候选字”识别器，并让其输出与底部目标字相同的中文标签：

1. 继续采集 9 个新 round，每轮 30 张；采样流程无需额外手写汉字答案。
2. 使用底部目标区的高置信识别结果和手动点击顺序，生成顶部候选字的训练标签。
3. 以 `round-001` 至 `round-006` 训练，`round-007` 与 `round-008` 验证，`round-009` 与 `round-010` 保留为从未调参的最终测试集。
4. 对 PP-OCR 的候选字输入做领域适配训练，并增加针对颜色、曲线干扰、旋转和笔画粗细的增强。
5. 只有独立测试集达到预先设定的正确率和置信度门槛后，才在插件中启用“建议点击”；自动点击仍应单独开关并在低置信时回退手动。

现有选课内容脚本可复用验证码截图、状态提示、Popup 配置和点击执行。中文识别器需要独立实现与训练，不能直接复用统一认证页的英数 Tesseract/CNN 模型。

PP-OCR 实验模型和 Python 依赖仅存放于被 Git 忽略的 `data/click-captcha-experiments/`，不会进入扩展包或发布版本。
