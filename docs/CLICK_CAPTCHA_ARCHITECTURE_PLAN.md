# 点击式中文验证码识别架构方案

## 目标与约束

- 第一目标是让插件的自动识别真正好用：优先提高整张验证码的点击顺序准确率，而不是追求单字 OCR 指标或论文创新。
- 第二目标是稳定、快速且可部署：推理完全在浏览器本地完成，低置信结果回退人工点击，现有插件流程始终可回退。
- 优先复用成熟算法、预训练模型和现有实现。只要现成方法达到发布门槛，就停止自研架构并直接工程化。
- 只有现成方法经过正确预处理、微调和融合后仍达不到期望，才针对已确认的瓶颈设计新架构；论文价值最后再判断。
- 当前 `round-001` 至 `round-010` 用于开发；冻结方案后另采全新轮次作为最终测试集。

## 问题重述

每张图片给出三个或四个清晰目标字，以及四个经过旋转、缩放、着色及背景干扰的候选字。候选字可能重复；真正任务不是在数千个汉字类别中做分类，而是在固定的四个候选位置中，为每个目标字寻找一个不重复的位置：

```text
3/4 个目标字形  ->  3/4 x 4 匹配分数矩阵  ->  24 种有序不重复点击序列中的最优结果
```

这个重述可以绕开 406 个字符类别、每类只有少量样本的问题，也允许模型匹配训练中从未出现过的汉字。当前所有已标注的 `round-001..010` 都是四目标数据；三目标数据必须单独保留为后续的冻结验证集，不能以四目标结论替代。

## 已完成的离线验证（2026-07-22）

固定开发划分为 `round-001..006` 训练、`round-007..008` 验证、`round-009..010` 开发测试。后者此前已参与 DINO 开发，只能用于趋势检查，不能作为最终泛化结论。

| 方案 | 验证集 | 开发测试集 | 结论 |
| --- | ---: | ---: | --- |
| DINOv2 CLS + 区域灰度 + 排列损失 | `17/60` | `24/60` | 静态背景淹没候选字形。 |
| DINOv2 CLS + **仅上方候选区**背景残差 + 排列损失 | `40..42/60`（三种子） | `43..45/60` | 背景减除是决定性预处理。 |
| DINOv2 + 将下方目标字也做背景中位数减除 | `12/60` | `18/60` | 淘汰：下方可变文字在中位数中产生笔画伪影。 |
| PP-OCRv5 + 候选背景残差 + `-60°..60°` 多角度 | `27/60` | `26/60` | 独立不足，但与 DINO 错误互补。 |
| 分数级融合（固定权重由验证集选择） | `50..52/60`（`83.3%..86.7%`） | `55..57/60`（`91.7%..95.0%`） | 当前最强离线方案，三种子均复现。 |
| 轻量全局学生 + 候选 `-45/0/45` 旋转 | `33/60`（`55.0%`） | `39/60`（`65.0%`） | 比无旋转学生略好，但不足以部署。 |
| 轻量局部 token Chamfer 学生 | `23/60`（训练至 30 epoch） | 未继续 | 局部 token 版本更慢且不如全局学生，停止该实现。 |

融合采用四个目标与四个候选的 `4 x 4` 分数矩阵，对 24 个排列枚举。PP-OCR 的离散文本匹配分数经每样本标准化后作为 DINO 排列分数的辅助项；在三个随机种子中，验证集均选出 `0.5` 或 `0.75` 的辅助权重。相较 DINO 单独预测，融合在验证集每种子改对 `9..12` 张、仅改错 `1` 张。

这些结果确认了两个部署边界：PP-OCR ONNX 模型约 `16 MB`，DINOv2 小模型主干约 22M 参数且 CPU 特征提取约 `2.8 s/张`，二者都不应原样进入浏览器扩展。它们应作为离线教师、标注器或蒸馏目标；现有英数登录验证码流程不受影响。

## 现有方案的问题

1. DINOv2 全局 CLS 特征和 PP-OCR 文字结果各自都不够可靠，但二者的误差具有可利用的互补性。
2. 背景中位数仅适用于候选区；底部目标字包含随机文字，不能整体做静态背景建模。
3. 直接部署 DINOv2 需要较大的主干和多次高分辨率编码，PP-OCR 也有显著的包体和多角度推理开销，均不适合作为浏览器首选实现。
4. `round-009/010` 已经参与早期 DINO 开发，当前高分不能替代全新冻结测试集。
5. 单纯 Siamese 模板匹配、局部最优传输、中文验证码检测都已有相关工作，不能单独作为论文创新点。
6. 轻量局部 token Chamfer 在这批数据上没有形成准确率信号；不能因为它听起来更贴近字形就继续堆叠实现复杂度。

## 方法梯队

下面不是预先指定必须实现的新架构，而是从成熟、低风险方案逐级验证。前一级达到发布门槛时，后续研发立即停止。

### 第一梯队：成熟的无训练字形配准

上方候选区使用多轮中值背景做静态背景减除，再结合颜色饱和度得到字符前景；下方目标区直接二值化。每个字形进行紧致裁剪、中心化和尺度归一化，并生成轮廓、骨架和距离变换。

每个目标/候选对在有限旋转、缩放和剪切范围内计算：

- 双向 Chamfer 距离；
- 骨架方向直方图相似度；
- 连通分量、孔洞数等拓扑一致性；
- 配准形变代价。

得到 `4 x 4` 分数后直接枚举 24 种排列。该级无需模型和汉字标签，速度快，对未见汉字也成立。Shape Context 等经典方法已经证明轮廓点的一一匹配可以处理尺度变化、小形变和离群点，因此它应当作为第一条强基线，而不是继续从 OCR 分类开始。[Shape Context](https://vision.ucsd.edu/publications/2002/shape-matching-and-object-recognition-using-shape-contexts)

### 第二梯队：成熟模型的正确复用

依次验证以下现有方法，不重新发明网络：

1. 修正 DINOv2 的标准输入 transform，使用 patch token 配合现成的局部最近邻、DeepEMD 或 Chamfer 汇总，不再使用整槽 CLS 作为唯一特征。
2. 使用 PP-OCR 识别干净目标字，并微调现有 PP-OCR 移动识别模型处理上方候选字；通过字符一致性得到排列。
3. 按论文和官方实现复现 SiameseCCR/Deep Template Matching，并替换当前可能不一致的数据预处理和训练设置。
4. 对上述方法做分数级融合和置信度校准。融合仍只在现有方法之间进行，不先增加手工字符规则。

若其中任何单一方法或成熟方法融合达到发布门槛，直接选择准确率最高且浏览器性能可接受的方案接入插件。

### 第三梯队：选择性级联

如果不同成熟方法各自擅长不同样本，可以采用简单级联：高间隔的结构匹配直接输出，困难样本才运行较慢的 OCR 或预训练特征匹配。该层的目标是提高整体准确率并降低平均耗时，不追求方法创新。

### 最后手段：轻量局部笔画匹配器

只有前三个梯队仍无法达到发布门槛时，才实现自研网络：

只在第一级排列间隔不足时运行神经网络：

```text
目标 mask/skeleton/distance  -> target stem --+
                                                +-> shared tiny encoder -> local stroke tokens
候选 RGB/residual/mask       -> candidate stem -+
```

- 两个浅层 stem 处理上下区域的域差异，后续主干共享。
- 使用 GroupNorm 或 LayerNorm，避免小批量 BatchNorm 不稳定。
- 保留局部特征图，不做单一全局池化。
- 使用双向 soft-Chamfer 或轻量最优传输汇总局部笔画对应，并允许无信息背景进入 dustbin。
- 八个字形各编码一次，再计算 16 个轻量相似度，避免执行 16 次完整网络。

DeepEMD 表明局部特征的最优匹配比单一图像向量更适合少样本任务，并能降低背景区域影响；本项目可采用更小、更易导出的 soft-Chamfer 近似，而不是照搬其昂贵求解器。[DeepEMD](https://openaccess.thecvf.com/content_CVPR_2020/html/Zhang_DeepEMD_Few-Shot_Image_Classification_With_Differentiable_Earth_Movers_Distance_and_CVPR_2020_paper.html)

#### 整码级排列训练

网络输出分数矩阵 `S`。对每个排列 `p` 计算：

```text
score(p) = sum(S[i, p[i]])
P(p) = softmax(score(p) / temperature), p in 24 permutations
```

训练直接最小化正确排列的交叉熵，并增加行、列对比损失。推理仍枚举 24 种排列，既准确又比通用 Sinkhorn/Hungarian 运行库更容易在浏览器部署。

置信度使用最佳与次佳排列的校准间隔、排列熵和前景质量共同决定。未达到阈值时返回 `manualRequired`，绝不自动点击。

#### 语义 OCR 旁路

PP-OCR 只作为可选旁路：高置信识别下方目标字，再与候选 OCR 或本地字体模板交叉验证。它不作为主路径，因为字符类别长尾会限制未见字泛化。现有 1104 个高置信标签仍可用于错误分析、字符不相交测试和合成数据生成。

## 自研阶段的数据与训练策略

1. 真实样本只需要点击顺序，不要求人工标注汉字类别；每张图自然产生 4 个正对和 12 个同图困难负对。
2. 使用下方干净字形生成大量上方风格的合成正对，变换参数从真实候选的角度、尺度、颜色、抗锯齿和前景残差分布估计。
3. 可用修正后的 DINOv2 patch token 或 PP-OCR backbone 作为离线教师，蒸馏局部相似度到小模型；DINO 不进入发布包。
4. 开发阶段使用按轮次分组交叉验证，并额外建立字符不相交划分，单独报告未见汉字表现。
5. `round-009/010` 已参与调参，只能算开发测试。冻结全部参数后采集至少 4 个新轮次，最终测试只运行一次。

## 实验顺序与停止条件

| 阶段 | 实验 | 决策 |
| --- | --- | --- |
| A | 背景减除 + Chamfer/Shape Context/骨架 + 24 排列 | 达标则直接部署；否则保留为融合特征 |
| B | DINOv2 排列匹配 + 候选背景残差 | 已验证为强离线教师；不直接部署 |
| C | PP-OCR 多角度候选识别 | 已验证为互补离线教师；不直接部署 |
| D | B/C 的校准融合 | 已达到离线整体 80% 目标；进入冻结测试与蒸馏设计 |
| E | 轻量非对称局部匹配器 + 24 排列损失 | 用 B/C 作为蒸馏教师，优先于从零训练 |
| F | 合成预训练、教师蒸馏和模型压缩 | 仅用于提升 E 的明确失败项 |
| G | 浏览器 Worker、量化和回退机制 | 最终候选通过新测试集后接入 |

每一步只改变一个主要变量，保存逐样本分数矩阵、改对/改错列表、三随机种子均值和耗时。未证明有效的模块不进入下一阶段。

## 发布门槛

- 普通辅助提示：高置信预测精度至少 95%，并报告覆盖率。
- 自动点击：全新测试集高置信预测精度至少 99%，覆盖率至少 60%。
- 整体整码准确率目标不低于 80%，同时报告字符不相交测试结果。
- 选择方案时准确率优先；确认准确率后再做量化、蒸馏和缓存优化，不用过早的 3 MB 限制排除更准确的成熟模型。
- 热态推理先以不影响登录体验为准，再根据候选模型实测制定 `p95` 和包体上限；冷启动单独统计且模型只加载一次。
- 模型异常、超时、样式漂移或低置信全部回退人工操作。

## 论文可行性

论文不是本项目的前置约束。若成熟方法达到要求，就以插件效果为终点，不为了投稿强行重做架构。仅将 PP-OCR、DINOv2 或 Siamese 网络用于验证码也不构成足够创新；已有研究已经覆盖中文字符模板匹配、少样本中文 CAPTCHA 识别和点击验证码端到端检测，例如 [Deep Template Matching](https://arxiv.org/abs/1811.06347)、[SiameseCCR](https://ietresearch.onlinelibrary.wiley.com/doi/10.1049/iet-ipr.2019.0618) 以及[基于目标检测的点击验证码攻击](https://ietresearch.onlinelibrary.wiley.com/doi/10.1049/ise2.12047)。

只有阶段 E/F 的自研方法相对成熟基线在全新测试集上取得稳定、可复现的显著提升，才评估以下论文表述：

> 面向低资源、开放字表和跨域退化场景的类别无关字形集合匹配：通过背景感知的非对称局部描述、整排列监督和选择性推理，在不识别字符语义的条件下完成一一对应。

可能贡献包括：

1. 将大字表识别重述为类别无关的集合到集合字形匹配。
2. 面向干净提示字和复杂候选字的非对称前景表示与局部笔画匹配。
3. 直接优化整排列准确率，并提供可校准的拒识机制。
4. 在浏览器端实现小模型选择性级联，给出准确率、覆盖率、延迟和体积的联合评测。

当前 300 张数据不足以支撑强论文结论，尤其最终测试只有 60 张。若要投稿应用型期刊或会议 workshop，建议最终拥有至少 1,000 至 2,000 张跨日期真实样本、300 张以上冻结测试集、公开可复现的合成生成器，以及经典形状匹配、OCR、SiameseCCR、DINO 全局/局部特征和所提方法的完整消融。原始线上验证码数据是否可以公开，应先确认学校授权和隐私/安全要求；否则发布脱敏合成数据与特征统计。

## 推荐决策

按 A 到 D 的顺序先把现有方法跑透，并在每一阶段检查是否已经达到“整体至少 80%、自动点击高置信精度至少 99%”的门槛。达到后直接进入浏览器工程化；全部未达到时，再根据逐样本错误归因决定是否启动自研局部集合匹配器。插件成功之后，若自研部分确实带来稳定增益，再单独评估论文。
